# Архитектура

## Слои

```text
браузер (src/client)
   │  HTTP: статика, /health, /status
   │  WebSocket: JSON-команды и сообщения
   ▼
src/server/http/http-server.js      белый список файлов, служебные endpoint'ы
src/server/websocket/websocket-server.js  heartbeat, лимит payload, коды ошибок
   ▼
src/server/rooms/room-manager.js    сессии, столы, таймеры, переподключение
   ▼
src/server/game/blackjack-table.js  состояние стола: раздача, ходы, выплаты
src/server/game/rules.js            чистые правила: очки и выплаты
src/server/game/cards.js            Card, Deck, Hand
```

## Ответственность

- **Транспорт** ничего не знает о правилах: принимает JSON, вызывает `RoomManager.handle` и превращает исключения в `{ type: "error", code, message }`.
- **RoomManager** владеет жизненным циклом: `sessions` (соединения), `playerSessions` (игрок → соединение), `rooms` (столы), `reservations` (сохранённые места), `pendingJoins` (запросы на места за столами, заполненными ботами), `phaseTimers` (ставки, ход, пауза после раунда), `dealerTimers`, `emptyTableTimers`. Идентификатор игрока (`playerId`) стабилен и не зависит от соединения, поэтому переподключение не ломает очередь ходов. Если полный стол занят ботами, запрос игрока ставится в очередь и бот заменяется, когда стол снова может принять игрока.
- **BlackjackTable** — единственный источник истины по деньгам и картам. Не делает ввода-вывода и не знает про WebSocket. Типы ботов, их ставки и решения по стратегиям инкапсулированы в `game/bot-strategies.js`; стол хранит ботов как обычные места игроков с типом стратегии. Ставка бота автоматически рассчитывается от его баланса при добавлении и перед каждым раундом.
- **rules.js** — чистые функции без состояния: их можно проверять без стола и таймеров.

## Автоцикл стола

Все команды проходят через `RoomManager.handle` → `afterCommand` → `advance`:

1. `advance` снимает TTL пустого стола, при отсутствии подключённых игроков переводит стол в `waiting` и заводит таймер удаления.
2. Если стол в `waiting`, вызывается `table.openBetting()` — так игра стартует сама, как только кто-то сел.
3. `syncTimers` выставляет ровно один таймер, соответствующий фазе: шаг дилера, ход игрока, дедлайн ставок или пауза после раунда. Затем состояние рассылается игрокам — клиент получает `timer.remainingMs` уже в этом снапшоте.
4. Если все подключённые игроки нажали «Готов», `finishBetting` запускает раунд досрочно; иначе это сделает таймер окна ставок.

## Таймеры

| Таймер | Владелец | Назначение |
| --- | --- | --- |
| Приём ставок | `phaseTimers` | окно 10 секунд (`BETTING_TIME_MS`) |
| Ход игрока/бота | `phaseTimers` | авто-пас игрока через 60 секунд; задержанный автоматический ход бота |
| Пауза после раунда | `phaseTimers` | 5 секунд на просмотр результата (`ROUND_PAUSE_MS`) |
| Шаг дилера | `dealerTimers` | пошаговое вскрытие карт с задержкой |
| Хранение места | `reservations` | окно переподключения (`RECONNECT_GRACE_MS`) |
| Пустой стол | `emptyTableTimers` | удаление через 5 минут (`EMPTY_TABLE_TTL_MS`) |

Таймеры инжектируются через `setTimeoutFn`/`clearTimeoutFn`, поэтому тесты работают на фейковом времени без реальных задержек.

## Надёжность

- исключение в таймере дилера перехватывается, раунд аварийно рассчитывается (`forceSettle`), сервер продолжает обслуживать столы;
- `drawCard()` пересобирает шуз вместо падения на пустой колоде;
- `split()` сначала тянет карты, потом меняет состояние — ошибка не оставляет стол в полусобранном виде;
- heartbeat отключает мёртвые соединения, освобождая места;
- `SIGINT`/`SIGTERM` корректно останавливают HTTP и WebSocket.

## Почему так тестируется

`deckFactory` и `setTimeoutFn` — точки внедрения зависимостей. Благодаря им тесты детерминированы: любая раздача задаётся списком рангов, а задержки дилера прокручиваются вручную.
